--- how this was produced ---
Source: docs/liveprobe_s15 (main.go, hauling.go, dispatch.go).

It builds and boots the REAL driver-hauling-service and
driver-dispatch-delivery-service binaries against a certification PostgreSQL
and Redis, then drives their HTTP surfaces the way Vendor Service, Fleet and
an operator console do: HMAC-v2 signed internal calls, a provider bearer
token, and unsigned calls that must be refused. Every PASS above executed
against a process listening on a socket.

To reproduce (the probe has no go.mod of its own; copy it into the workspace
to build it):

  cp -r docs/liveprobe_s15 shared/go/cmd/liveprobe_s15tmp
  (cd shared/go && go build -o /tmp/liveprobe_s15 ./cmd/liveprobe_s15tmp)
  rm -rf shared/go/cmd/liveprobe_s15tmp

  HAULING_LIVE_DATABASE_URL='postgres://.../hauling_live?sslmode=disable' \
  DISPATCH_LIVE_DATABASE_URL='postgres://.../dispatch_live?sslmode=disable' \
  LIVE_REDIS_ADDR='127.0.0.1:6399' \
  /tmp/liveprobe_s15

Hauling migrates its own database on boot (HAULING_MIGRATION=true), so its
database must be empty. Dispatch does not, so its database must already have
the migration chain applied.

Downstream dependencies (Fleet events, Wallet, Notification, Media) are
deliberately pointed at a closed port: this probe certifies routing and
authorization, and a dependency that answered would make the result depend on
services this run does not own.
