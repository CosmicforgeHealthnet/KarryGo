# API Gateway

Routes requests from customer, provider, and admin apps to the correct Cosmicforge Logistics
service. This should become the only public backend entry point for client apps.


## Internal Callbacks

`/api/v1/internal/callbacks/*` is the additive HTTP callback path for dispatch and payment-wallet lifecycle events. These routes require `X-Internal-Service-Key` and do not accept partner API keys or dashboard session JWTs.

Dispatch callback examples:

```bash
curl -X POST "$BASE_URL/api/v1/internal/callbacks/trip-started" \
  -H "Content-Type: application/json" \
  -H "X-Internal-Service-Key: $PARTNER_INTERNAL_SERVICE_KEY" \
  -d '{"event":"trip.started","booking_id":"dispatch-booking-id","provider_id":"11111111-2222-3333-4444-555555555555","rider_name":"Taiwo Adeleke","rider_phone":"+2348033445566","rider_rating":4.85,"vehicle_color":"Red","vehicle_model":"Honda CB125","plate_number":"LAG-234-XY","occurred_at":"2026-07-05T10:08:00Z"}'

curl -X POST "$BASE_URL/api/v1/internal/callbacks/provider-arrived" \
  -H "Content-Type: application/json" \
  -H "X-Internal-Service-Key: $PARTNER_INTERNAL_SERVICE_KEY" \
  -d '{"event":"trip.provider_arrived","booking_id":"dispatch-booking-id","provider_id":"11111111-2222-3333-4444-555555555555","occurred_at":"2026-07-05T10:06:00Z"}'
```

After `trip-started`, `GET /api/v1/partner/v1/deliveries/:id` returns the saved rider and vehicle snapshot plus a `tracking_url` when `rider_id` is present.

Payment-wallet charge result example:

```bash
curl -X POST "$BASE_URL/api/v1/internal/callbacks/charge-result" \
  -H "Content-Type: application/json" \
  -H "X-Internal-Service-Key: $PARTNER_INTERNAL_SERVICE_KEY" \
  -d '{"source_reference":"invoice-id","status":"success","reference":"paystack_ref","amount_kobo":500000}'
```

Redis Pub/Sub subscribers remain enabled during the transition. Do not remove them until dispatch HTTP callbacks, customer-service callbacks, api-gateway callbacks, payment-wallet job/refund/charge endpoints, and the end-to-end lifecycle have all been confirmed live without duplicate partner webhooks.

## Partner Web Signup and Onboarding

The Partner Web App signup flow is email OTP first:

1. `POST /api/v1/partner/v1/auth/signup/start` with `business_email`.
2. `POST /api/v1/partner/v1/auth/signup/verify` with `business_email` and the 6-digit `otp_code`.
3. Use the returned Partner Session JWT as `Authorization: Bearer <token>`.
4. `PATCH /api/v1/partner/v1/profile` during onboarding for business info, logo URL, and profile photo URL.

The legacy password endpoints remain available for existing flows:

```text
POST /api/v1/partner/v1/auth/register
POST /api/v1/partner/v1/auth/login
```

They are not the Partner Web App signup path. OTP-created accounts have `password_hash = NULL`, so password login fails with generic `invalid_credentials`.

### Public OTP Endpoints

`POST /api/v1/partner/v1/auth/signup/start`

```json
{ "business_email": "dev@pharmacare.com" }
```

Sends the verification email and returns:

```json
{
  "success": true,
  "message": "A verification code has been sent to your email."
}
```

`POST /api/v1/partner/v1/auth/signup/verify`

```json
{
  "business_email": "dev@pharmacare.com",
  "otp_code": "042391"
}
```

On success, the account is created as `active` on the `sandbox` plan and the response includes the dashboard session JWT. No API key is auto-generated by OTP verification.

`POST /api/v1/partner/v1/auth/signup/resend`

```json
{ "business_email": "dev@pharmacare.com" }
```

Resend is rate limited by `PARTNER_OTP_RESEND_COOLDOWN_SECONDS`.

OTP security notes:

- Codes are 6 digits generated with `crypto/rand`.
- Plaintext OTPs are never stored, logged, or returned by the API.
- The database stores only a SHA-256 hash.
- Verification uses the latest challenge for the email; older codes stop working after resend.
- Expired, consumed, or max-attempt challenges are rejected.

### Profile Onboarding

After OTP verification, the frontend patches the profile with the session JWT:

```json
{
  "business_name": "PharmaCare Nigeria Ltd",
  "business_phone": "+2348033445566",
  "state": "Lagos",
  "city": "Ikeja"
}
```

Logo and personal profile photo files are uploaded to media-file-service. The API Gateway only stores the returned URLs:

```json
{ "business_logo_url": "https://firebase.storage.example/logo.jpg" }
```

```json
{ "profile_photo_url": "https://firebase.storage.example/photo.jpg" }
```

All profile fields are optional and partial updates only change fields present in the request.

### Partner OTP Email Configuration

```env
PARTNER_OTP_TTL_MINUTES=10
PARTNER_OTP_MAX_ATTEMPTS=5
PARTNER_OTP_RESEND_COOLDOWN_SECONDS=60
PARTNER_SMTP_HOST=mail.yourdomain.com
PARTNER_SMTP_PORT=465
PARTNER_SMTP_USERNAME=your-email@yourdomain.com
PARTNER_SMTP_PASSWORD=your-cpanel-email-password
PARTNER_SMTP_FROM=your-email@yourdomain.com
PARTNER_SMTP_FROM_NAME=KarryGo
PARTNER_SMTP_TLS_MODE=tls
```

Partner OTP email currently uses cPanel SMTP directly from api-gateway. This is temporary and can later be moved to notification-service.

Real credentials go in `services/api-gateway/.env`; never commit `.env`. Only placeholders belong in `.env.example`. Use cPanel Email Accounts to create or retrieve the SMTP mailbox password.
